Data-Free Analysis of the FPS Cross-Attention Adapter

This document outlines two key data-free analyses to verify the functional properties of the FPS Cross-Attention Adapter. These tests are designed to be run directly on the model's weights, bypassing the need for data sampling and full inference loops, providing a direct and reproducible measure of the adapter's learned behavior.

The core principles we aim to verify are:

Functional Orthogonality: The conditional signal (motion blur) should operate in a functional space that is independent of the content signal generated from the text prompt. This prevents context drift.

Low-Rank Representation: The adapter should learn a simple, compact, and efficient representation for the conditional effect (e.g., motion blur), indicating good generalization.

Analysis 1: Principal Orthogonality Check

This analysis tests the functional separation between the adapter and the backbone. It simulates the attention mechanism's response to the most fundamental "content primitives" of the pre-trained model and measures how orthogonally the adapter's signal combines with the resulting content signal.

Methodology: The "Principal Component Showdown"

Extract Backbone Primitives:

Load the original, pre-trained backbone model.

For each adapted cross-attention block, perform a Singular Value Decomposition (SVD) on the query (W_q), key (W_k), and value (W_v) projection weight matrices.

The left singular vectors (U_q, U_k, U_v) represent the orthonormal bases for the principal queries, keys, and values the model can produce. These are our "content primitives."

Synthesize a Test Bench:

Construct a set of synthetic attention inputs by selecting the top N (e.g., N=64) vectors from each of the primitive bases:

q_test (from U_q)

k_text_test (from U_k)

v_text_test (from U_v)

Simulate Attention with the Trained Model:

Load your final, trained model (Backbone LoRA + Adapter).

For a strong condition (e.g., c=1), deterministically generate the adapter's k_fps(c) and v_fps(c).

Simulate the Text Pathway: Calculate the output that would be generated if the principal primitives were used as inputs.

y_text_principal = flash_attention(q_test, k_text_test, v_text_test)

Simulate the FPS Pathway: Calculate the output generated by the adapter in response to the principal queries.

y_fps_principal = flash_attention(q_test, k_fps(c), v_fps(c))

Measure Orthogonality:

Compute a representational similarity score between the two outputs, y_text_principal and y_fps_principal.

Recommended Metric: Centered Kernel Alignment (CKA) or Singular Vector Canonical Correlation Analysis (SVCCA).

Interpretation

Success (Low Similarity Score): A CKA/SVCCA score close to 0 indicates that the adapter's functional output is orthogonal to the backbone's principal content outputs. This is strong, data-free evidence that the adapter is well-disentangled and will not cause context drift.

Failure (High Similarity Score): A high score indicates a "feature space collision," where the adapter's signal interferes with the backbone's content representation, creating a high risk of generation artifacts.
